# STAR-like mother covariance in CeeV0Lite 0.6.x

## What changed

The old implementation calculated `sigmaMassGeV` from two independent
daughter momentum covariance blocks:

```text
Var(M) = g1 C1 g1^T + g2 C2 g2^T.
```

That expression has no place for the correlation generated when both tracks
are fitted to the same decay vertex, and it treats a common T0 as two unrelated
timing errors.

Version 0.5.0 follows the important data flow used by STAR KFParticle:

1. transport both daughter states while numerically retaining the derivative
   of their closest paths;
2. fit one common SV from both tracks' transverse measurements in a symmetric
   batch update;
3. use the one effective two-track DCA residual after eliminating both path
   nuisances;
4. construct one `(SV,P,E)` mother state;
5. rerun the complete estimator under 12 input perturbations to obtain the
   mother covariance, then calculate mass and mass uncertainty from it.

It is a compact scalar implementation, not a copy of STAR's SIMD class tree.

## Joint common-vertex update

The input ordering is

```text
x = (x1,y1,z1,px1,py1,pz1, x2,y2,z2,px2,py2,pz2).
```

The detector errors of the two input tracks are initially independent, so
`Cx=diag(C1,C2)`.  Each track has a free path parameter.  Consequently a
two-prong vertex has one effective pair residual after both paths are
eliminated.  With `n=unit(u1 cross u2)`, the final local constraint is

```text
q(x) = n dot (r2-r1) = 0,
H = (-n, 0, +n, 0).
```

`ConstructMotherAtCommonVertex()` applies

```text
S     = H Cx H^T + Rfloor
K     = Cx H^T S^-1
xfit  = x - K q
Cfit  = Cx - K (Cx H^T)^T.
```

The off-diagonal 6x6 daughter block in `Cfit` is the effective
`C_proton,pion = Cov((r_proton,p_proton),(r_pion,p_pion))` generated by this
shared-secondary-vertex consistency residual. It is not a scalar, a physical
interaction term, or a named STAR class member. The input model starts from
`diag(C_proton,C_pion)`, so upstream proton--pion correlations are assumed zero.
The local cross block is used during the central-state projection but is not
retained as a separate public matrix. Constraining all three components of
`r2-r1` here would be wrong: it
would turn the two unmeasured path parameters into artificial measurements.

## Mother state and mass

The public mother ordering is fixed:

```text
y = (SVx,SVy,SVz,Px,Py,Pz,E).
```

with

```text
SV = (r1fit+r2fit)/2
P  = p1fit+p2fit
E  = sqrt(p1fit^2+m1^2) + sqrt(p2fit^2+m2^2).
```

The production covariance of an accepted candidate is obtained by treating the
full POCA/vertex estimator as `F:R^12->R^7`.  Each input coordinate is perturbed,
all closest paths and the common vertex are solved again, and

```text
J = dF/dx,
Cy = J diag(C1,C2) J^T.
```

This outer Jacobian contains the `ds_closest/dx` effect that would be lost by
propagating at a fixed path. Rather than publishing a daughter cross block, it
directly folds correlations induced by the currently implemented
closest-path/common-SV map into `Cy`. `MotherMassAndError()` then uses

```text
M = sqrt(E^2-P^2)
g = (0,0,0,-Px/M,-Py/M,-Pz/M,E/M)
sigmaM^2 = g Cy g^T.
```

A significantly negative mass variance is reported as invalid; only tiny
floating-point roundoff is clamped to zero.

At finite `By`, each point-to-helix closest-path solve uses exact transverse
periodicity to reduce the global search to at most two periods around the
longitudinal optimum. It enumerates every stationary point in that window,
rejects local maxima, evaluates the original endpoints, and selects the global
distance minimum. This prevents a
single Newton start from choosing the wrong helix turn. It does not turn
`daughterDcaCm` into a simultaneous global two-helix DCA, and it does not add a
field map or material model.

## Shared CEE event time

This section applies to real data (or a dedicated digitization that explicitly
simulates the T0 detector). Ordinary simulation uses the exact generator origin
`startTimeNs=0`, with both common sigmas zero and shared-time propagation off;
it neither binds nor reads `CeeT0Hit`. The per-hit stop-detector resolution
`sigmaTofTimeNs` remains active.

`event.sigmaStartTimeNs` and `additionalDecayTimeSigmaNs` describe common
candidate-level timing uncertainty.  Specifically, the latter is defined here
as the width of an independent common scalar offset in
`t_decay = T0 + t_parent + delta_common`; it is not a per-daughter resolution.
`sigmaTofTimeNs` must therefore mean the
stop detector's own resolution, not a value which already includes T0.  The
common terms are excluded from both independent
daughter covariance blocks.  For a candidate that has already passed the
cheap central-value cuts, the complete TOF fixed-point is solved again at

```text
T0 +/- sharedTimeDerivativeStepNs
T0 +/- sharedTimeDerivativeStepNs/2.
```

The two central derivatives must pass a configured stability comparison.  The
half-step result gives `b=dy/dT0`, and the common contribution is added once:

```text
Cy <- Cy + b b^T *
      (sigmaStartTimeNs^2 + additionalDecayTimeSigmaNs^2).
```

This full rerun includes the feedback through daughter momenta, parent beta,
decay time and secondary vertex.  It is more complete than inserting only a
local analytic `dp/dT0` term. Real data should enable this after calibrating its
common timing errors. Simulation deliberately keeps
`FinderConfig::propagateSharedTimeUncertainty=false` because no measured T0 term
exists there.

## Topology and daughter-to-PV metrics

The common-vertex fit provides `geometricChi2` and `geometricNdf`. Applying the
mother production-vertex constraint provides a two-dimensional contribution
`primaryVertexConstraintChi2`, with NDF 2. The candidate total is

```text
topologicalChi2    = geometricChi2 + primaryVertexConstraintChi2
topologicalNdf     = geometricNdf + 2
topologicalChi2Ndf = topologicalChi2 / topologicalNdf.
```

This accumulated form follows the STAR data flow more closely than the 0.5.x
field, which exposed only the PV-constraint term under the name
`topologicalChi2Ndf`. The PV-only values remain separately available for QA.

Daughter-to-PV `GetDeviationFromVertex()` values in the inspected STAR code
are raw chi2, not `sqrt(chi2)`. CeeV0Lite therefore uses
`daughterChi2FromPv[i]` and `minimumDaughterChi2FromPv` as the canonical metric
and cut. `daughterPvSignificance[i]`, the deprecated
`daughterDeviationFromPv[i]`, `minimumDaughterDeviationFromPv`, and the old CLI
flag retain the historical `sqrt(chi2)` interpretation for backward-compatible
steering only.

## ROOT output

`CeeV0Analysis` output format 2 introduced:

- `energyGeV`;
- `motherCovarianceValid`;
- `motherCovarianceStatus`;
- `motherCovariance[28]`.

The 28 values are the lower triangle in row-major order:

```text
C00,
C10,C11,
C20,C21,C22,
...
C60,...,C66.
```

Units follow the state ordering: position-position entries are `cm^2`,
position-momentum/energy entries are `cm*GeV`, and the final 4x4 block is
`GeV^2`.

Output format 3 retains those fields and adds explicit numerator/NDF/component
branches:

- `geometricChi2`, `geometricNdf`, `geometricChi2Ndf`;
- `topologicalChi2`, `topologicalNdf`, `topologicalChi2Ndf` (the total above);
- `primaryVertexConstraintChi2`, `primaryVertexConstraintNdf`,
  `primaryVertexConstraintChi2Ndf` (PV-only QA);
- `daughterPvChi20`, `daughterPvChi21` (raw chi2);
- `daughterPvSignificance0`, `daughterPvSignificance1` (`sqrt(chi2)`).

Output format 4 retains all preceding branches and adds complete outer-
Jacobian diagnostics:

- `motherJacobianComplete` and `motherJacobianPerturbationFailed`;
- attempted, succeeded and failure counts over all 24 perturbation sides;
- separate 12-bit plus/minus failure masks;
- the first failed column, side and `VertexFitStatus`;
- `covarianceDependentCutsEvaluated`.

`motherCovarianceStatus` uses the enum order in `CeeV0LiteTypes.h`:

```text
0 NotCalculated
1 Valid
2 VertexUpdateFailed
3 NumericalPropagationFailed
4 SharedTimeDerivativeFailed
5 NonFinite
6 NotPositiveSemidefinite
7 ProcessNoiseUnsupported
8 JacobianPerturbationFailed
```

Strict output still has `motherCovarianceValid=1` and status `1`. With the
explicit `--allow-incomplete-mother-jacobian` QA option, status `8` may be
written when the nominal candidate succeeded but at least one outer numerical
perturbation fit failed. Its covariance-dependent branches are `NaN`; recover
the strict sample with `motherJacobianComplete==1`. Status values `2--7` remain
hard rejections. Output format `4` is recorded in
`TNamed("CeeV0AnalysisConfig")`, not in a separate tree branch.

## What is still not identical to STAR

- STAR evaluates analytic mutual-DCA/Jacobian terms and vectorizes candidates;
  this reference implementation uses central differences and uniform `By`.
- Non-zero stochastic transport process-noise rates are deliberately rejected
  by the outer mother-covariance calculation until their independent modes are
  added to the 12D propagation.
- The compact candidate does not retain a permanent joint state containing
  PV, SV, both daughters and T0.
- Correlations absent from CEE input files, such as upstream track--track or
  PV--track correlations, cannot be reconstructed.
- Daughter-to-PV topology metrics use daughter marginal states and do not
  retain the shared-T0 cross block.
- In TOF mode, independent track-state errors are propagated from the converged
  states through the vertex estimator, but are not yet rerun through the whole
  TOF fixed point; the common T0 derivative is.
- PV covariance feedback through the parent flight-time equation is not yet
  included in mother momentum/mass covariance.
- `daughterDcaCm` is evaluated after separate point-to-helix transports to the
  fitted-vertex estimate, not by a simultaneous global two-helix minimizer.
- Non-uniform field maps, material transport, and additional pointing or maximum
  decay-length cuts are not introduced by the 0.6.0 metric changes.

Therefore, under the assumption of independent upstream track inputs, the
vertex-estimator-induced effective `C_proton,pion` and the double-T0 problem are
addressed at the mother level. Correlations absent from the input are not
created. The result remains a STAR-inspired lightweight reference,
not a bitwise or coverage-equivalent STAR KFParticle replacement.  Final cuts
still require CEE simulation pull and coverage studies.

## Regression tests

`make test` covers:

- mother covariance symmetry and finite diagonals;
- invariance under swapping non-intersecting daughter states;
- invariance of the central result under moving a reference state along the
  same zero-field trajectory (with its covariance transported consistently);
- closest-path-aware numerical mother covariance and PSD checks;
- a deterministic small-error toy-MC comparison of sampled and propagated
  mass width;
- direct `(P,E)` mass-error propagation;
- exact rank-one common-nuisance addition;
- rejection of a clearly negative mass variance;
- zero-field TOF, zero-field tracking and finite-field reconstruction;
- `sigma(T0)` doubling gives four times the T0 covariance increment.
- finite-field point-POCA multi-root/global-minimum and local-maximum rejection;
- exact total/PV-only chi2--NDF identities and raw-versus-square-root daughter
  cut boundaries.
